- Linux, and x86-64: this machine is macOS arm64. Whether a `Debug` build
  or a missing `-ffp-contract=off` changes any bit with glibc on x86-64 is
  not known; the two tests for them may be unable to fail there (they
  cannot fail wrongly: the references are the same operations).
- `pixi run cm-check --monitor nav2_collision_monitor`: the task asks for
  the Lean node only.
- The reviewer's scripts `side_by_side.py`, `param_probe.py`,
  `ffi_probe.py`, `fp_probe.sh`, `leak_probe.cpp`: they record the state at
  `cb25673` and were not re-run; the comparison with upstream is T02's.
- The warning for a configuration without zones has no test: a parameter
  file or `-p` cannot express `polygons: []` (rcl refuses it), as the draft
  already says in `smoke_node.py`.
- No pull request.

## Found wrong or changed

- **Finding 8 had no test.** Reproduction before this task: in `on_cmd`,
  return `false` after the `switch`; every test passed. Now: mutants 8a, 8b.
- **No test noticed the removal of `-ffp-contract=off`.** Reproduction: in
  the package's `CMakeLists.txt` replace `-ffp-contract=off` by
  `-ffp-contract=fast`, build, run `smoke_conversions` of the draft: 0
  failures. Now 1 failure ("1000 readings with a pose: no multiplication is
  fused with an addition").
- **The harness can crash at the start of a scenario** (not changed: the
  file is not this task's). `test/scenario.py:793` takes element 0 of
  `get_publishers_info_by_topic('cmd_vel_out')` right after
  `wait_connected`; in the first full run the list was empty once and
  `reference_scenario` ended with `IndexError` (the node under test there is
  the Python reference node, not the Lean node). It happened once in two
  full runs, the one during which other node tests were running on the
  machine; I take it for a race under load, which is an inference, not
  something I reproduced. For T02/T07, which own the harness: wait until the
  list is not empty.
- Nothing false was found in the model, the theorems or the SPEC. No
  statement was weakened.

## Friction

- `pixi run test` takes 20 to 25 minutes, almost all of it real-time
  waiting, and one run was lost to the harness race above.
- Checking that a test can fail needs a second copy of the packages, since
  the colcon tests read `smoke_node.py` and `example.yaml` from the source
  tree while they run. The mutation script and the selective runner for
  `smoke_node.py` were kept out of the repository (scratch files); they
  would be worth a place under `review/` if such checks are wanted again.
- An unreachable branch (finding 8) could only be tested after moving it
  out of the node into a function without ROS.
