## Found wrong or changed

Verified by a run unless marked "inferred".

1. **T03's fix for a negative `/clock` and upstream's wait for a transform
   do not fit together as SPEC_NAV2.md 8.3 proposed them.** The node runs
   without rclcpp's clock thread (D15), so under simulated time its clock
   cannot advance inside a callback; `tf2_ros::Buffer::lookupTransform` with
   a timeout would then never time out (inferred from tf2's loop, which
   reads the node clock; not run). The node therefore has its own loop
   (`wait_for`): upstream's rule (10 ms sleeps while the clock is before
   start + `transform_tolerance`, one more attempt at the end) around a
   lookup that never waits, and while it waits it takes the `/clock`
   messages of its own subscription by hand. T07's scenarios on the wait
   pass to the nanosecond (`tf-missing`, `tf-tolerance-decimal`,
   `tf-tolerance-0.3`, `tf-wait-timeout0`, `shift-*`). This loop is trusted
   code in the node, not in `transforms.hpp`. SPEC_NAV2.md 8.3 says so now.
2. **The interface.** As SPEC_NAV2.md 8.1–8.3 proposed, with: kind 5 for a
   withheld velocity; after a failed scan lookup with a non-zero source
   timeout the zones' lookups are not made (upstream does not reach its
   zone loop; the core leaves the shapes unchanged then); the zone-vertex
   array ends after the last zone that has vertices.
3. **Theorems restated or dropped.** `foldl_exec_not_ok`,
   `cm_not_ok_after`: a monitor that is not ok starts unconfigured like any
   other, so it answers `stopSource` when active and nothing otherwise
   (before: always active). `exec_st_of_not_ok` is gone (false now: a
   lifecycle call changes the phase); `apply_st_of_not_ok` and
   `apply_out_of_not_ok` take its place. `cm_readBack_at` (every call of a
   sequence) is dropped; `cm_readBack_after` holds after every prefix, which
   covers every command. `cmOnScan_unusable_stop`, `Call.raw`,
   `Call.coords`, `coordsAfter`, `startState_eq`, `run_startState` went with
   the definitions they were about. No statement was weakened to get a
   proof through. **Nothing in the model was found false**, and the model's
   event definitions are untouched.
4. **Commands without a clock reading are not in `Call`** (as T03 left it):
   the end-to-end theorem does not speak of sequences that contain them.
5. **ND5 is checked in C++.** Zone names never reach the core, so "two
   zones of one name, a zone named `invalid source`, an empty name" is
   refused by the shim when it reads `polygons`. Listed as trusted (T3).
6. **Cleanup drops the monitor.** `on_cleanup` delivers `cleanup` and then
   destroys the core's monitor; the next `configure` builds a new one from
   the parameters. The model's state after `cleanup` and a new `State.init`
   differ only in `stopStamp`, which is not read while `prevZero` is false.
   So the end-to-end theorem covers one life of a monitor, from configure
   to cleanup.
7. **The parameter callback** rejects every change (ND8) except the
   declarations `on_configure` itself causes: the TF listener declares QoS
   overrides for `/tf` and `/tf_static`, and rejecting those failed the

## Friction

- The session's worktree guard refuses shell commands with heredocs or
  with `git` next to anything else; every multi-line edit went through a
  script file. One such script truncated `FFI.lean` (it opened the file for
  writing before a failing expression); restored from the commit made
  minutes before, nothing lost.
- macOS has no `timeout`; a non-interactive bash ignores `kill -INT` for
  background children, so two ad-hoc scripts of mine hung until I killed
  their processes by PID.
- `rclcpp_components` gives a component no global arguments: parameters of
  the container's command line do not reach it; they must be in the load
  request.
- The TF listener declares parameters during `on_configure`; a node that
  rejects parameter changes rejects those too.
- THEOREMS.md links to line numbers; every edit of a proof file moves them.
  A script looked every name up again (as T05b's did; again not committed).
