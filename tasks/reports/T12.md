## Found wrong or changed

Nothing in the SPEC, the model, the node or the tests was changed. Found
(details and reproduction in `docs/AUDIT.md`, "Findings"):

1. **The tree does not build on Linux through pixi** (plain Ubuntu 24.04,
   arm64): `ros/roslean_core/CMakeLists.txt` runs `${CMAKE_STRIP}`, which
   is not found; and `test_cm_ffi` uses `std::thread` and is linked without
   `Threads::Threads`, which the environment's glibc 2.28 sysroot needs.
   With `apt-get install binutils` and `LDFLAGS=-pthread` everything
   passes.
2. `pixi run cm-check` hangs without a display and does not say why.
3. With Nav2's unchanged `nav2_params.yaml` the node prints `2 parameters
   refused`; the README and `gaps.html` quoted `1 parameter refused`
   (corrected).
4. The collision monitor links of the pages point to `main`, where their
   targets are not yet; `details.html` linked a `docs/` that nothing builds
   (removed).
5. The headline cost table's raw data is not in `bench/results/` (the files
   there are T02's); re-measured, the table holds within 7 %.
6. `gaps.html` says "4 to 9 times" once, "6 to 9 times" elsewhere.
7. `pixi.lock` gives Linux upstream 1.3.13; the pages name 1.3.12 and
   1.3.14.
8. Three sentences leave out a hypothesis of their theorem (source enabled;
   node active; a fixed shape in `run_stop`).
9. `pixi.toml`'s comment on `test-quick` ("a minute or two") and the
   CMakeLists' "about 4 MB" are out of date.
10. The tests and launches leave files in `/tmp` (164 after one `test-quick`
    and one `test`); removed here by hand.

## Friction

- No `timeout` on macOS; a 15-line Perl wrapper that kills the process
  group was used for every long command.
- The session's tooling refused any shell command that mentioned `git`
  together with other commands, and `git` outside the worktree, so the
  fresh clone was made with a single plain `git clone` and its commit read
  from the file under `.git/`.
- Waiting for a 39-minute test run in a session that cannot sleep: polling
  in three-minute pieces.
- CMake caches a tool that was not found: after installing `binutils` the
  build failed in the same way until the build tree was removed.
- `ros2` command-line calls in the fresh clone left two `ros2` daemons
  running, and one node survived the end of its `ros2 run`; all three
  ended by PID.
