## Done

**Model** (`core/ROSleanCore/CollisionMonitor.lean`;
`CollisionMonitorXform.lean` is renamed `CollisionMonitorPoint.lean` and
holds what is left of it; no Mathlib in `core/`).

- The transform is gone from the model: `Xform`, `Xform.usable`, `Xform.mat`,
  `Xform.pointMm`, `Xform.vertexMm`, `Dy`, `Mat`, `truncMm`, `roundMm`,
  `Point.far`, `Placement`, `TopicShape.raw` and `TopicShape.place` are
  removed.
- **The command event is `cmd now v scanPts zoneVerts`.**
  `scanPts : Option (List Coords)`: the base-frame coordinates of the
  readings of the stored scan, **one pair of binary64 patterns per reading,
  valid or not**, in scan order, as the shim computed them for this command;
  `none` if there was no usable transform. `zoneVerts : List (Option (List
  Coords))`: for each zone the base-frame vertices of its stored message, or
  `none`.
- The shape event is `shape k verts foreign`, `verts : Option (List Coords)`
  the message's vertices in the base frame, `none` if the lookup failed.
- `Beam` is the range pattern only. `Scan.fits s c` (one pair per reading),
  `Scan.points s c` (reading `i` with pair `i`; pairs of readings that are
  not valid dropped; the rest through `scanPointMm`, which is `coordMm` on
  each coordinate, as before T05).
- `vertexCoordMm`, new: a binary64 vertex coordinate rounded to the nearest
  millimetre on machine words; a value that is not finite or is 1024 m or
  more becomes ±`coordLimit`, which no shape may reach. `placeVerts`,
  `TopicShape.ofMessage`, `TopicShape.refresh` use it.
- Two checks are new, because the coordinates now come from the shim:
  scan coordinates that are not one pair per reading count as a failed
  lookup (E8 step 3); zone vertices that are not as many as the shape has
  are not taken (step 4).
- Everything else of T05 is as it was: lifecycle, `Output.answer`, reports,
  R15, the fail-open cases as upstream.

**Why this representation.** Bit patterns and not millimetres, so that the
conversion (truncation toward zero, saturation, NaN) stays inside `step` and
inside the theorems, and the shim still converts nothing. One pair per
reading and not one per valid reading, so that R4 and the number of points
stay decisions of the model taken from the stored scan: the shim can neither
add nor drop a point (`points_length`). Cost: 16 bytes per reading and
command also for readings that do not count.

**What the stored scan still decides, and what it does not.**

- Of the stored scan alone: its age (R7, `stale` unchanged); which readings
  are valid (R4); the number of points: `points_length` (if the coordinates
  fit, exactly the number of valid readings, whatever the coordinates),
  `points_length_le` (never more, for any coordinates), `points_eq_nil_iff`.
- Of the command: where each counted reading lies (`points_eq`,
  `mem_points_iff`, `coordMm_eq_truncReal`, `coordMm_sub_lt`).
- Trusted: that pair `i` is the image of reading `i` of the scan the model
  has stored, under the right transform. The model checks the count only.

**The margin for option A** (`Margin.lean`; SPEC_NAV2, section 5). Per axis,
with `u` upstream's point, `s` the shim's, `m` the model's:

- Proved: `|m − s| < 1 mm` unless saturated (`coordMm_sub_lt`); a topic-zone
  vertex within 1/2 mm of the shim's (`vertexPointMm_sub_le`);
  `contains_of_close`: vertices within `dv`, point within `dp` of a boundary
  point, `2·(dv + dp)² ≤ 5` ⟹ counted; and with `δ` the distance between the
  shim's and upstream's values as a hypothesis: `contains_of_shim` (topic
  zone, **δ ≤ 1/25 mm**), `contains_of_shim_fixed` (fixed polygon, **δ ≤
  2/25 mm**), `circle_safe_shim` (circle, **δ ≤ 1/2 mm**).
- Prose, as before: the topological half ("the boundary passes over the
  point").
- Trusted (T7, T2): that `δ` is that small. Estimate, not proved: both are
  evaluations of the same expression in `double` on the same seven numbers
  from tf2, the shim's never fused (`-ffp-contract=off`, decided), upstream's
  arm64 binary fused; each is within about 5·10⁻⁹ mm of the exact image for
  coordinates below 1000 m, so `δ` is of the order of 10⁻⁸ mm. SPEC_NAV2
  allows 10⁻⁶ mm. The budget of 0.04 mm is 40,000 times that allowance.

## Found wrong or changed

- **Nothing in T05's model was found false.** The rework removed theorems
  that cannot be stated without a transform; no statement was weakened to
  make a proof go through. Where a hypothesis was added
  (`points_eq_nil_iff`, `output_filter_validBeam`, `evaluate_isStop_mono`:
  "the coordinates fit"), the statement without it is false: with too few
  pairs a scan with valid readings has no points.
- **ND7 moves to the shim.** Under option B the model refused a transform
  with a number that is not finite or with a zero quaternion. The model no
  longer sees the transform. If the shim applied such a transform, the
  coordinates would be NaN, `coordMm` makes `+coordLimit` of a NaN, and the
  point would lie in no zone: fail-open. SPEC_NAV2 (ND7, 8.4, T6) and the
  T06 brief now say that the shim checks the seven numbers and hands over
  "none". tf2 does not return such a transform, by its source as T04 read
  it.
- **A list of coordinates of the wrong length with `source_timeout: 0`**
  gives "no points" (the command passes), like a missing transform (N27).
  Consistent with upstream's rule, and fail-open. With a non-zero timeout it
  is the stop for an invalid source (`wrong_count`).
- **The interface as it stands** (`CollisionMonitorFFI.lean`): signatures
  unchanged. `Monitor.placed : Bool` became `Monitor.coords : Option (List
  Coords)`: a scan call remembers the coordinates of its records (they are
  in the base frame already) and every command carries them; `none` after
  an unusable scan. A monitor starts with `coords := none` where it had
  `placed := true`; before the first scan call no scan is stored, so the
  answer is the same (R8). Scan coordinates are kept as `Nat` patterns; a
  pattern with the sign bit set is a big number in Lean's runtime, which
  costs an allocation per negative coordinate per scan. T06 replaces these
  calls.
- **`maxRecDepth`** is raised for two examples in `Examples.lean` (the
  elaborator's `decide` runs out of depth on `zip`/`filter`/`map` over six
  readings with the conversion inside). The kernel checks them as it does
  the others; no `native_decide`, no `decide +kernel`.
- **Outside the files the task lists: nothing.** The module list in
  `ros/roslean_core/CMakeLists.txt` and the two import lists follow the
  renamed module.
- **Left as they are, not mine to change:**
  `docs/collision_monitor/COMPARISON.md` (T02) explains the node's slowness
  by `Xform.pointMm`, which no longer exists; its measurements are of the
  model before this task. The comment on `scanUnusable` in
  `ros/roslean_core/include/roslean_core/collision_monitor.hpp` (T06).
  `review/collision_monitor/nav2/TransformCost.lean` (the prototype of B)
  stays as history.

## Questions for the user

1. **A valid reading whose coordinate is not finite** becomes a saturated
   point outside every zone, as before T05 (SPEC.md, "Far and non-finite
   points"). With the transform in C++ this is where a bad transform or an
   overflow in the shim would end up. Keep it (as before, as upstream), or
   let the model answer with the stop for an invalid source when a reading
   that counts has a coordinate that is not finite? The second is
   fail-closed and a numbered difference from upstream; it is a small
   change in `sourcePoints` and its theorems.
2. **Coordinates of the wrong length with `source_timeout: 0`** let the
   command pass (above). Keep, or stop regardless of the timeout? It cannot
   happen with a shim that works as specified.
3. **The check on the number of vertices at a refresh** (a foreign shape
   takes new vertices only if they are as many as it has) is my addition,
   so that "a refresh moves vertices and does nothing else" is a theorem.
   Upstream has no such check and no way to violate it. Say if it should
   go.
4. T07 is running: the note added to its brief may not be seen by that
   session.

## Friction

- `decide` in the elaborator fails with "maximum recursion depth" on a list
  computation that the kernel checks at once; the message does not say
  which function.
- `cases h : f x` does not rewrite `f x` under a `match` that has not been
  reduced; `simp [h]` in each branch does.
- `simp only […] at h` left `decide (a ≤ b) = true` in place although
  `decide_eq_true_eq` was listed (and reported it as unused); `omega` then
  ignores the hypothesis silently. `of_decide_eq_true` by hand.
- THEOREMS.md links to line numbers; every edit of a proof file moves them.
  A script that looks each name up again was needed
  (not committed: it is twenty lines of Python).
- The shell tool refused compound commands with `(…) &` and heredocs in
  this worktree, so every multi-line edit went through a script file.
