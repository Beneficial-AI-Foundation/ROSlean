## Done

**Model** (`core/ROSleanCore/CollisionMonitor.lean`, and the new
`core/ROSleanCore/CollisionMonitorXform.lean`; no Mathlib in `core/`).
SPEC_NAV2.md, section 3, as written:

- State: `phase` (`unconfigured`, `inactive`, `active`, `finalized`),
  `shapes` (one entry per zone), `prevReport`, next to `scan`, `prevZero`,
  `stopStamp`. `State.init cfg` is unconfigured.
- Events: `configure`, `activate`, `deactivate`, `cleanup`, `shutdown`
  (E1–E5); `scan now s` (E6); `shape k verts place` (E7); `cmd now v scanTf
  zoneTfs` (E8). A missing transform is `scanTf = none`, not an event.
- Zones: `ZoneShape.fixed s` or `ZoneShape.topic`; `TopicShape` (`raw`,
  `foreign`, `current`); `acceptShape`, `TopicShape.refresh`, `liveConfig`.
- `Report` (`normal`, `stop k`, `slowdown k`, `source`), `Action.report`.
- `Output`: `silent` or `answer velocity report`; `answer none none` is not
  `silent`.
- `Beam` carries the scan-frame coordinates as two binary64 patterns;
  `Scan.points s t` places them with `Xform.pointMm`.
- `Xform`, `Xform.usable`, `Xform.identity`, `Xform.pointMm`,
  `Xform.vertexMm`: the first two rows of the 3D rotation and the
  translation, exactly, on dyadic integers (`Dy`); zero terms are never
  aligned.
- `step` is total. `Event.scanUnusable` is removed (SPEC_NAV2, section 9,
  edit 10). There was no `Monitor.dropScan` on the base commit.

## Found wrong or changed

**In SPEC_NAV2.md, section 4: two statements false as written.** The model
was not changed; the theorems state what holds; the document is corrected.

1. *Shape accepted (iff): "a `shape` event changes the state iff it is
   accepted."* Counterexample: the same accepted message twice. The second
   is accepted and the state is unchanged (`step_shape_same`; an example in
   `Examples.lean`). True and proved: the conditions of E7 hold iff the
   message installs a shape; a refused message changes nothing; an accepted
   one sets `shapes[k]` and nothing else; so the state changes only if the
   message is accepted.
2. *Lifecycle invariants: "if `phase ≠ active` then `prevZero = false` and
   `prevReport = normal`."* False in the finalized phase. Counterexample:
   `configure`, `activate`, a finite command with no scan stored and a
   non-zero `source_timeout`, `shutdown`: the state is finalized with
   `prevZero = true`, `prevReport = source` (an example in `Examples.lean`).
   E5 changes the phase only. True and proved: the clause for the
   unconfigured and the inactive phase (`Inv.quiet`), which is all that
   "After activation" needs.

**Made precise.**

3. `Xform.identity.pointMm x y = (coordMm x, coordMm y)` holds for finite
   `x`, `y`. For `x = −∞`, `y = 0` the left side is `(coordLimit,
   coordLimit)` (section 3.1) and the right side `(−coordLimit, 0)`. Both
   are outside every accepted zone.
4. "No shape" on runs: "the last cleanup" has to be one that took effect.
   Proved for any history that leaves the node unconfigured.
5. `State.init` takes the configuration, so that `shapes` has one entry per
   zone from the start.
6. `Xform.vertexMm` is not saturated (a vertex beyond the limit is refused
   anyway), so "within 1/2 mm" holds without exception.

**Outside the files the task lists, one line.**
`ros/roslean_core/CMakeLists.txt`: `ROSleanCore/CollisionMonitorXform` added
to `ROSLEAN_MODULES`. The list of generated C files is written out there;
without the new module the library does not link and no node builds. Also
the two import lists `ROSlean.lean` and `core/ROSleanCore.lean`.

**The C interface (`CollisionMonitorFFI.lean`, `FFI.lean`): kept working,
not extended.** The exported functions have the same signatures (the build's
signature check passes) and, by the tests above, the same behaviour. How the
old calls are read in the new model, for T06 to replace:

- `cmNew` starts the monitor after `configure` and `activate`
  (`startState`), because no call delivers a lifecycle event.
- `Monitor` has a new field `placed`. A scan call always delivers `scan`
  and sets `placed := usable ≠ 0`; a command call delivers `cmd` with
  `scanTf := some Xform.identity` if `placed`, `none` if not, and
  `zoneTfs := []` (`cmdEvent`). An unusable scan therefore stops the robot
  by "No transform" where it did by the removed event; with
  `source_timeout: 0` it leaves "no obstacle", as before.
- `beamAt` stores the two coordinate patterns unconverted; `coordAt` is
  gone, `u64At` moved into the core.
- `roslean_cm_out_kind` is 0 for `silent` **and** for `answer none _` (the
  node publishes zero for an unknown kind, so 5 could not be introduced
  here). `readBack_eq` is about `Output.velocity`; the report is not
  exposed.
- A monitor that is not ok answers `stopSource` in the active phase and
  follows lifecycle events.
- No builder call makes a topic zone.
- Still to remove elsewhere: the comment on `scanUnusable` in
  `ros/roslean_core/include/roslean_core/collision_monitor.hpp`; the
  sections of SPEC.md from "Shim boundary" on (SPEC_NAV2, section 9, edits
  1–8 and 10–20).

**Cost, measured.** `test_cm_ffi` now takes 169 s. All of it is its leak
test: 650,000 rounds, each with three commands that place a scan of 64
readings, about 1.3 µs per reading and command. That is the figure
SPEC_NAV2, section 5, predicts for option B (1.2 to 1.9 µs); before, the
conversion was made once per scan. Inference, not measured: `pixi run
test-quick` is longer by about that much. T06's benchmark decides whether
the fixed-point form is needed.

**Not proved** (said in THEOREMS.md): that `Xform.identity.vertexMm` is the
same integer as `vertexMm` of a fixed polygon's vertex (each is proved within
1/2 mm of the same number); the topological half of the polygon claim, as
before; upstream's floating-point error (T7), which is not provable here.

## Friction

- `decide` could not check an example in which a zero coordinate met a
  denominator of 2¹⁰⁷⁴: the elaborator does not evaluate a power whose
  exponent is above 256.
  A zero numerator is now never aligned (`Dy.scaled`), which is also what
  the design asks for.
- `split` does not see through a `let` in a definition (`dsimp only`
  first); `simp` closes goals in one branch of `cases … <;> …` and not in
  the other, which the "flexible tactic" linter then reports.
- Two namespaces `F32` (`CollisionMonitor.F32` and
  `CollisionMonitorFFI.F32`) both define `neg`; with both open the name is
  ambiguous.
- macOS has no `timeout` command; long commands were given the tool's
  limit instead.
- The list of Lean modules in `ros/roslean_core/CMakeLists.txt` is written
  by hand, so a new core module breaks the link until it is added.
