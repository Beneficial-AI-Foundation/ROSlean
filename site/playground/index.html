Playground

A robot patrols a circle. Put a box in its way, drive it yourself, or press the emergency stop, and watch what twist_mux and the collision monitor decide.

What runs here. Which command the mux forwards, and whether the monitor passes, slows, stops or withholds it, is decided by the same Lean functions the ROS nodes run, compiled to WebAssembly. The robot, the lidar, the boxes, the planner and the base are a toy simulation written for this page.

The theorems are about the Lean functions and are checked by Lean, not by this page: the mux theorem, two of the monitor's. What the C++ shim does in the real nodes (the scan's points, the transform, the slowdown multiplication) is done here by JavaScript, and is no more verified than the C++ is. What is real here and what is not

From the Lean code, through the same C interface the nodes use: the mux's priorities, timeouts and lock; the monitor's lifecycle state, which readings of a scan count, the conversion of each point to whole millimetres, the test of each point against each zone, min_points, the choice of action, and when a zero is withheld. Both are configured with the parameters of the project's Gazebo demo.

Not modelled here:

  • Late or missing scans. The Lean code checks the scan's age against source_timeout on every command, but this lidar always delivers on time, so that stop never occurs.
  • Transforms. The lidar sits at a fixed offset from the base. There is no tf2, no failed lookup, and no correction for motion since the scan (the demo does not use it either): while the robot turns, the points the monitor works with lag behind the boxes by up to a fifth of a second, as drawn.
  • Lifecycle. The monitor is configured and activated once, at the start and at each reset.
  • The C library's arithmetic. The scan's points are computed by JavaScript's cos and sin, not the ones the C++ node calls; a point can differ in its last bits.
  • Sensor noise. Every ray hits exactly where the box is.
  • Physics. The robot moves exactly as commanded, and a box neither moves nor gives way.
  • Message timing. Every message is handled at once and in order. Nothing is delayed or lost.
  • The rest of the nodes. Circle zones, zones fed by a topic, a clock without a valid reading, parameter checks and logging are in the Lean code or the C++ shim and are not used on this page.
